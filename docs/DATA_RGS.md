# Трекер RGS

**Формат не окончательный.** Пользователь пришлёт итоговый вариант позже.
Поэтому чтение делать через маппинг колонок (см. PLAN, раздел 4), а
расчёты — на нормализованных полях `rgs_items`.

`examples/rgs_tracker_example.xlsx` — реальные данные трекера
Азербайджана на 13.11.2026 (69 позиций), но уже в упрощённом виде:
одна строка заголовков с понятными названиями. Лист «Ню Буквы» — словарь
кодов статуса.

## Исходный трекер (как он выглядит у пользователя)

Файл «Отчёт RGS», главный лист «Е»: заголовки в строках 2–3, данные с
5-й строки, 82+ колонки. Известные колонки:

| Колонка | Что в ней |
|---|---|
| I | TM ENG — торговое название |
| — | TM RUS |
| K | GENERIC — МНН |
| L | FORM |
| M | DOSAGE |
| N | PACK |
| O | статус (код из «Ню Буквы») |
| — | CATEGORY: M (лекарство), FS (БАД), MD (медизделие) |
| — | ОЛ (ФИО): IZ или ЧС — ответственный |
| — | MFG — производитель; PARTY — заявитель (MAKROMED, PHARMCONTROL) |
| — | Упр Ктг — группа: 01 подано, 02 подача сен–ноя, 03 долгосрочная подготовка, 04 зона риска, СТОП |
| — | Dossier, Artwork, Leaflet, CPP/FSC, Sample, WS, COA — чек-лист документов |
| — | Дата получения задачи, ЗД (запрос досье), АД (анализ досье) |
| AJ | Подано в ГНЦЛ (факт подачи) |
| AS / AT | Preliminary Expertise: Invoice receipt date / Payment |
| AU / AV | Specialized Expertise: Invoice receipt date / Payment |
| BH | План подачи (майский план 14.05.2026) |
| BI | Подано в ГНЦЛ (майский файл) |
| BJ / BK | экспертизы по майскому плану |
| BL | План получения РУ (майский план) |
| AZ–BC | формулы сроков — сломаны (≈ −46 000 дней при пустых датах), не использовать |
| лист IN | новые позиции, у которых пока только название и статус |

Листы «СВОД», «Е (2)», «Лист1–5», «Пц Фй», «Шаблон» — старые версии и
черновики, не читать.

## Правила расчёта (согласованы в чате)

- **Дата подачи** = BI; если BI пустая — AJ.
- **План РУ** = BL + 2 месяца запаса. Подписывать «план от 14.05.2026 +
  2 месяца». Без BL — «нет плана».
- Если подали позже майского плана, план РУ не сдвигается; опоздание
  показывается в «Укладываемся ли в план».
- **Позиции с листа IN** — новые, входят в «Готовятся».
- **Стоп-позиции** в цифры дашборда не входят, показываются отдельно.
- Сроки этапов считать заново по датам (медиана и среднее, только
  неотрицательные разности):
  - от задачи до запроса досье;
  - от запроса до анализа досье;
  - от анализа досье до подачи;
  - от инвойса до оплаты (обе экспертизы вместе).
- Разбивку по IZ/ЧС на обзоре **не показывать**. Фильтр по категории
  оставить.
- Оплаты (гос. пошлина, лаборатория, агент) **не показывать**.

## Статусы

| Код | Значение |
|---|---|
| (пусто) | новый, без статуса |
| d | запрошено досье |
| dc | старт сборки досье |
| dca / dcb | сборка < 50% / > 50% |
| dct | перевод досье |
| dh | досье передано агенту |
| dha | подано, ждёт экспертизы |
| dhp | подано, инвойс оплачен |
| dhp1 | оплачена первичная экспертиза |
| dhp2 | оплачена специализированная экспертиза |
| r | зарегистрировано |
| s… / w… / y… | приставки: стоп / ожидание / не проходит |

## Этапы на дашборде

Этап считается по датам, а не по коду:

| Этап | Условие |
|---|---|
| Готовится | нет даты подачи |
| Ждёт экспертизы | подано, нет оплаты первичной |
| Первичная оплачена | есть оплата первичной, нет оплаты специализированной |
| Специализированная оплачена | есть оплата специализированной |
| РУ получено | статус r (пока 0) |
| Стоп | группа СТОП |

«На каком этапе» («дошли» / «сейчас здесь»): берётся самый дальний этап
с датой из цепочки задача → запрос → анализ → подача → оплата первичной →
оплата специализированной, даже если промежуточная дата пустая.

## Блоки «Обзора»

1. Где мы сейчас: в работе, подано, РУ до конца года, РУ в следующем году.
2. На каком этапе: таблица этапов.
3. Когда получим РУ: столбики по месяцам на 13 месяцев вперёд; клик по
   месяцу → боковая панель: группы по производителю, одна строка на
   препарат (дозировки объединены «×2»), МНН / дозировка / упаковка
   раскрываются по клику. Ниже итоги к концу года, к середине следующего
   года, к концу периода.
4. Укладываемся ли в план: подано X из Y майского плана, в срок /
   с опозданием / медиана опоздания / не подано; четыре плитки сроков.
5. Что мешает: позиции, где плановая дата подачи прошла, а подачи нет —
   ТМ, производитель · МНН · форма, причина из комментария, плашка дней
   (жёлтая до 90, красная больше 90). Предложено, но не подтверждено:
   разделить на «долгосрочная подготовка» и «проблемные».
6. Остановлено: N · «Открыть список» → та же боковая панель, группы по
   причине.

В «Обзоре» у препаратов показывать ТМ, производитель, МНН, форма. Дозу и
упаковку — только в раскрытии и на «Препаратах».

## Несколько рынков

Каждая загрузка RGS привязана к рынку (`market_code`). Экран один, рынок
выбирается вверху. Правила (запас к плану, нормативы) — в настройках
рынка.
