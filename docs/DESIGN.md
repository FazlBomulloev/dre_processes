# Дизайн

Дизайн сделан на холстах Claude Design в стиле PharmDash и выгружен в
`design/`. Это эталон вида и поведения; в коде экраны собираются на
React-компонентах в духе `frontend/src/components` PharmDash.

## Как открыть

```bash
cd design
python -m http.server 8000
# http://localhost:8000/vpc/Main.dc.html
# http://localhost:8000/rgs/Main.dc.html
```

`support.js` в каждой папке — простой рендерер формата `.dc.html` для
предпросмотра. Через `file://` не работает, нужен http-сервер. Скриншоты
всех экранов — в `design/screenshots/`.

## Формат `.dc.html`

- Разметка внутри `<x-dc>`; `<helmet>` — шрифты и базовые стили.
- `{{ путь }}` — значение из `renderVals()`.
- `<sc-for list="{{ rows }}" as="r">` — цикл, `<sc-if value="{{ x }}">` —
  условие.
- В конце `<script type="text/x-dc" data-dc-script>` — класс `Component`
  с `renderVals()` (данные и расчёты) и `setState()` (интерактив).
- Стили — inline в атрибуте `style`; их нужно перенести в Tailwind/токены.

## Экраны ВПЦ (`design/vpc/`)

Шапка общая: плашка «ВПЦ», вкладки Предложения · Заводы · Страны ·
Воронка и динамика, справа капсула «Выгрузка ВПЦ · дата · N позиций» и
кнопка «Обновить выгрузку».

- **Main** — Предложения. Поиск МНН, фильтры-таблетки, тёмный блок
  выбранного продукта, таблица «Все предложения» с быстрыми вкладками
  состояний, «Колонки», «Excel».
- **Factories** — KPI, рейтинг заводов (предложения, МНН, страны, полоса
  состояний, ценовой индекс, до контракта), цена по стране завода,
  мини-профиль.
- **Countries** — плитки рынков, тепловая карта «страна × этап», откуда
  приходят предложения.
- **Funnel** — итоги периода, воронка с нормативами и «зависло», причины
  остановок, помесячная динамика.
- **Offer** — боковая карточка предложения.
- **FactoryProfile** — профиль завода, цена против рынка (точка на
  полосе разброса), лента событий.
- **Country** — страна: итоги, полоса этапов, ведущие заводы, зависшие,
  кто ведёт. Основа для раздела «ВПЦ · рынок».
- **Drill** — список предложений по клику: путь, фильтры-чипы, KPI,
  таблица по сроку в статусе.

Детальные экраны в дизайне показаны на одном примере (RONTIS,
Казахстан, АЦ). В коде клик открывает то, на что нажали.

### Что исправить при переносе

- На Main во вкладках «Стоп 4», а в полосе состояний «Стоп 3» +
  «Контракт, не в портфеле 1». В коде считать из данных.
- На Main подписи «14 предложений», а строк-примеров 10 — демо.
- Группа «Контракт» показана отдельно; итог зависит от решения по Кк
  (DECISIONS).
- Причины остановок в Funnel — пример. В выгрузке причины нет отдельной
  колонкой; предложить классификацию по последнему комментарию
  (ключевые слова) и согласовать.

## Экраны RGS (`design/rgs/`)

- **Main** — Обзор: шапка RGS + рынок + дата данных, фильтр категорий,
  блоки «Где мы сейчас», «На каком этапе», «Когда получим РУ» (клик по
  месяцу → боковая панель), «Укладываемся ли в план», «Что мешает»,
  «Остановлено» → панель.
- **Products** — Препараты: вкладки этапов со счётчиками, поиск, таблица
  (препарат с формой · дозой · упаковкой, этап, подано, план РУ),
  справа тёмная карточка выбранного препарата: план/факт/сдвиг подачи,
  все даты этапов, 7 документов, комментарий.

Цифры в дизайне RGS реальные и годятся как ожидаемый результат тестов:
в работе 62, подано 38, РУ до конца 2026 — 9, в 2027 — 36; из майского
плана подано 20 из 29; сроки этапов 3 / 48 / 193 / 14 дней; «что
мешает» — 9 позиций; остановлено 7.

## Принципы, которые пользователь подтверждал

- Сначала главное, детали — по клику (правило 5 секунд, перевёрнутая
  пирамида). Не больше 5–9 блоков на экране.
- Перегруз не нравится: лишнее прятать, широкие таблицы на обзоре не
  ставить, списки открывать в боковой панели.
- Длинные МНН и упаковки обрезать, полный текст — при наведении или в
  раскрытии.
- Графики-ради-графиков не нужны.
